SAP Service Layer

Service Layer normally listens on port 50000 with a self-signed certificate. Leave the box ticked unless you have installed a trusted certificate.

FBR Digital Invoicing

Tokens are issued from the IRIS portal and are valid for five years. They are stored encrypted with Windows DPAPI via Electron safeStorage.

Encryption is unavailable on this machine, so credentials are kept in memory only and must be re-entered each run.

Mapping defaults

Used only when the business partner has no usable province. Every invoice that relies on it is flagged with a warning, because the province affects the filing.

These two scenarios differ only by whether the buyer is registered, so the right one is a per-invoice fact. FBR rejects the wrong one with error 0205. No other scenario is ever changed.

Forces the rate on every line, e.g. 18%. The sales tax amount is recalculated to match, so the filing will state more tax than the SAP document shows. Use it when SAP's tax setup is wrong and you know the correct rate — every affected invoice is flagged in Preview.

These apply to any item that has no value of its own. Fine for sandbox testing; before production every item needs its real classification, because FBR checks the HS code against the sale type.

QR code for printed invoices

FBR requires every issued invoice to carry its logo and a QR code, version 2.0 (25×25) at 1×1 inch. A PNG is written per invoice and its path stored in U_FBR_QRPath for the print layout to pick up.

Regenerate covers invoices registered before this existed, or where generation failed.

Address defaults

FBR requires an address for both parties. These are used only when SAP has none — every invoice that relies on one is flagged with a warning, so a fallback can never pass unnoticed into a filing.

SAP user-defined field names

These must match the UDFs created in SAP. See scripts/sap-udf-setup.md for the exact definitions.

A standard SAP field can be named here instead of a UDF — for example UserText to read HS codes from the item master's Remarks. The code is extracted from free text, and standard fields are treated as read-only so the app can never overwrite what else they hold.
